# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm install               # one-time setup
npm run docs:dev          # local dev server (HMR)
npm run docs:build        # production build → docs/.vitepress/dist
npm run docs:preview      # serve the built dist
```

There is no test or lint script — verifying component or layout changes means running `npm run docs:dev` and clicking through. Markdown style is governed by `.markdownlint.json` (MD033, MD013, MD034 disabled). The site is written in Korean (`lang: ko-KR`).

Deployment is automatic: pushing to `main` triggers `.github/workflows/deploy.yml`, which builds with Node 20 and publishes `docs/.vitepress/dist` to GitHub Pages (custom domain `docs.the2davi.dev` via `CNAME`). The workflow uses `fetch-depth: 0` because `lastmod` is computed from git history — keep this if editing the workflow.

## Architecture

This is a VitePress 1.x site. All content and config live under `docs/`; the repo root only holds `package.json`, `tsconfig.json`, the workflow, and the `CNAME`.

### Four content sections

Top-level navigation is fixed to four sections, each with its own sidebar generation rules in `docs/.vitepress/config.mts`:

| Section | Sort | Notes |
|---|---|---|
| `articles/` | frontmatter `date` desc | flat, single depth |
| `notes/` | filename numeric prefix (`01-`, `02-`…) | nested folders, collapsed at depth 2 |
| `deep-dive/` | frontmatter `order` | per-project series, collapsed at depth 2 |
| `translations/` | frontmatter `date` desc | flat, single depth |

Sidebars are auto-generated by `vitepress-sidebar` via the `entry()` helper in `config.mts`. The helper short-circuits to `null` if a section folder doesn't exist, so removing a whole section from disk is safe. All sidebars share these excludes: `**/index.md`, `**/_embeds/**`, `**/_backups/**`, `**/bak-*.md`, plus any file with `draft: true` in frontmatter.

### Frontmatter is a contract

`docs/.vitepress/data/content.data.ts` defines the `DocItem` type and uses `createContentLoader` to glob all four sections. Cards, indexes, and the homepage feed all read from this loader, so frontmatter fields are load-bearing — not just metadata. Required/important fields per section are documented in `docs/frontmatter-conventions.md`; the loader's defaults (e.g. `order ?? 9999`, `status ?? 'active'`) define the fallback behavior when fields are missing.

When adding content, follow `docs/filename-conventions.md`: kebab-case, ASCII only (Korean filenames break GitHub URL encoding), and `NN-` prefixes for ordered series in `notes/` and `deep-dive/`.

Section index pages (`articles/index.md`, `notes/index.md`, `deep-dive/index.md`) filter the loader by `d.section === '<name>'`. A doc missing the `section` frontmatter field will silently disappear from its index page even though it builds and is reachable by URL — always set `section` to match the folder.

### Custom theme components

`docs/.vitepress/theme/index.ts` registers five global components used inside markdown via `<script setup>`:

- `ContentList`, `CategoryIndex`, `TagCloud`, `SeriesNav` — render filtered slices of `content.data.ts`. Section index pages (`docs/notes/index.md` etc.) import the loader and pass items in.
- `DocEmbed` — collapsible `<details>` that lazy-loads a section from another markdown file by `src` + `anchor`. It uses `import.meta.glob('../../../notes/**/*.md', { query: '?raw' })`, so its scope is **`notes/` only** — embedding from `articles/` or `deep-dive/` requires extending the glob in `DocEmbed.vue`. The component reimplements VitePress's slug rules; if VitePress changes anchor generation, the `slugify()` function here must be updated to match.

`theme/index.ts` also adds a custom resizable sidebar handle (only above 1280px breakpoint, width persisted in `localStorage` under `vp-sidebar-width`). Both `style.css` and `custom.css` exist; only `style.css` is imported (custom.css is dormant).

### Image conventions

Per `docs/image-rules.md`: document-local diagrams go in `docs/<section>/<project>/assets/` (move with the doc); OG/social images go in `docs/public/og/<slug>.png` (served from site root).

## Publication safety (Proxmox notes)

The Proxmox handbook subtree has a two-track publication model. Future Claude touching `docs/notes/linux/proxmox/` must identify the track before editing.

- **Internal preservation (v3 masking)** — `07-cmp-test/00-handbook-overview.md` through `10-recon-output-templates.md` + `README.md`. These retain environment-identifying detail (cluster name, node hostnames, IP planes) as load-bearing context. Do **not** apply external masking to these files; they are deliberately preserved with v3 for in-team learning. Masking policy lineage v1→v3 lives in `07-cmp-test/data-snapshots/`.
- **External release (v4 masking)** — `data-snapshots/masking-policy-v4.md` + `mask-v4.sh`. Two subtypes:
  - **Yellow** (mask-and-ship): `01-setup` ~ `06-references`. v4 sed maps `pve-nd0X` → `pve-nodeA-E`, `10.99/10.10.X.0/24` → RFC 5737/6598, blocks plaintext credentials at pre-check.
  - **Red** (extract-and-rewrite): meta-only generalizations of 07-cmp-test live in `docs/deep-dive/cmp-meta-handbook/` as a separate series. Never copy raw 07-cmp-test text into deep-dive — only abstract patterns.

**Black-tier files** (must never reach public history): `(CMP)통합테스트_*.csv` (PII + plaintext admin password), `kcy0122-test-prep-*.md` (peer identification), `07-cmp-test/04-storage-resource-management.md` (internal meeting agenda). The publication review (`docs/notes/blog-ops/proxmox-series-publication-review-2026-04-26.md`) §6.1 has the standing remediation checklist — read it before any push touching this subtree. `docs/notes/blog-ops/` is itself draft-sensitive; treat it as internal-only unless explicitly asked.

## Gotchas

- TypeScript config (`tsconfig.json`) only covers `docs/.vitepress/**` — markdown files aren't type-checked.
- The `_embeds/` and `_backups/` folders and `bak-*.md` files exist as drafts/sources for `DocEmbed` and are intentionally hidden from sidebars; don't "clean them up" without checking what references them.
- `07-cmp-test/data-snapshots/` (gitignore-marked) holds masking policy lineage and raw recon snapshots — don't relocate "for tidiness."
- `docs/deep-dive/cmp-meta-handbook/` is the public-facing meta extraction; verify zero environment identifiers (run the v4 leftover-pattern grep) before committing changes there.
- `docs/configurations.md` is documentation-of-the-config (an example for readers), not the live config — the live config is `docs/.vitepress/config.mts`. They will diverge; `config.mts` wins.
- The nav bar in `config.mts` includes a `Translations` link, but `docs/translations/` does not exist on disk yet. The sidebar `entry()` helper safely no-ops, but the nav link itself will 404 until the folder is created.
- `docs/deep-dive/index.md` filters out anything with a `series_order` set, so series members appear only in the sidebar — not on the section landing page. Use `series_order: 1` for the lead doc if you want it hidden from the index too.
