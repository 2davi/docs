# 축5 프롬프트 — 프로덕션 전략 (Production Strategy · 캡스톤)

> **사용법**: 공통 프롬프트(`00-common-prompt`)를 먼저 붙여넣고, 이어서 이 파일을 붙여넣는다.

## 이 채팅의 축
**축5 — 프로덕션 전략 (캡스톤).** 앞선 네 축의 조각을 실전에서 합칠 때의 *정책 결정*과 마감재. 가로지르는(cross-cutting) 축이라 시리즈의 종착점.

## 선행 학습 상태 (이전에 정복한 축 — 전부 완료)
- **코어(AbortController)** ✅
- **축1 (수명·정리)** ✅ — ERM/`using`, `WeakRef`/`FinalizationRegistry`.
- **축2 (EventTarget 기반)** ✅ — EventTarget, CustomEvent, 리스너 옵션.
- **축3 (합성·동시성)** ✅ — 결합자, 동시성 제한, cancel-previous.
- **축4 (스트림 취소)** ✅ — async 이터레이터, Web Streams, 백프레셔.
- 이번이 **축5 (마지막)**. 이후: 시리즈 통합 회고.
- *(직전 축[축4]의 인계 메모를 여기 붙여넣기)*

## 코어와의 연결점
앞선 축들이 "기법"이었다면, 축5는 그것들을 언제·어떻게 조합할지의 "전략"이다. 코어 위에 타임아웃·재시도·멱등성·테스트·측정을 다시 얹어 프로덕션 등급으로 만든다.

## 이 축의 하위 토픽 (왜 → 정의 → 사용 → 한계)
1. **왜**: 기법을 안다고 프로덕션이 되진 않는다. 전체 데드라인, 재시도 안전성, 누수 실측 같은 정책이 추가로 필요.
2. **타임아웃 전략**: 전체 데드라인 vs 시도별 타임아웃, `any()`로 데드라인+요청 시그널 합성.
3. **재시도·백오프**: 지수 백오프 + 지터, 취소 가능한 재시도 루프 설계.
4. **멱등성(idempotency)**: 재시도 안전성, Idempotency-Key. (네 `rest-domain-state-manager` 로드맵과 직접 연결.)
5. **취소 테스트**: 취소 경로 단위 테스트, `AbortSignal.abort()` 스텁, 타이머/타임아웃 모킹.
6. **누수 실측**: 힙 스냅샷, `WeakRef` 기반 검증, 장수 프로세스에서의 timeout/any 실측(명세상 GC 가능 ≠ 런타임 실제 GC).
7. **생태계 서베이**: `TaskController`/`scheduler.postTask`(AbortController를 **상속**), Web Locks(`navigator.locks`), Node(`timers/promises`, streams).
8. **시리즈 통합 회고**: 코어 + 5축을 하나의 멘탈 모델로 봉합.

## 시작 지시
**진단 질문 1개**(예: "재시도를 N번 하는 함수에 AbortSignal을 끼울 때, '전체 데드라인'과 '매 시도 타임아웃'을 동시에 만족시키려면 시그널을 어떻게 구성하나?")로 시작. 채점 후 1번부터.

## 마감
이 축이 끝나면 공통 프롬프트 §6 **"축 마감 점검 의식"**을 실행하되, **시리즈 전체 회고**를 추가한다 — 코어부터 축5까지의 의존 지도를 한 장으로 요약하고, `index.md` 허브에 남길 최종 정리 항목을 제시한다.
