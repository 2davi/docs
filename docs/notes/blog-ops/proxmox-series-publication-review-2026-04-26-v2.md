### 0.2 본 보고서의 평가 전제

다음 전제는 v1과 다르며, 평가 결론에 직접 영향을 준다.

1. **레포지토리는 private 상태로 운영된다** — 소스 자체는 외부 공개되지 않음. 평가 대상은 빌드 산출물(`docs/.vitepress/dist/`)이 GitHub Pages를 통해 `docs.the2davi.dev`에 배포되는 자산뿐.
2. **git history는 정리된다** — v1 §6.1의 "CSV 즉시 제거 + filter-repo"는 본 시점 이후 history rewrite로 일괄 처리될 예정. 따라서 **과거 평문 비밀번호·CSV·draft 파일의 git history 잔재는 본 보고서 시점에 해소되는 것으로 가정**.
3. **사내 보존본 `07-cmp-test/`은 빌드 단계에서 제외되는 것이 정상** — 외부 공개판은 `docs/deep-dive/cmp-meta-handbook/`로 분리 완료. 사내 보존본은 사이트에 노출되어서는 안 된다.

### 1.2 정성 검증

자동 grep을 통과했다고 해서 외부 공개 적합한 것은 아니다. 다음을 별도 점검했다.

#### 1.2.1 명령 블록 안 마스킹 IP

`mask-v4.sh` [8] 단계가 `192.0.2.X`·`198.51.100.X`·`203.0.113.X`·`100.64.0.0` 패턴이 명령 블록(```bash·```sh)에 박혔는지 검사. 본 시점에 모든 14개 Yellow 파일이 [8] 단계 통과(WARN 미발생). v2 §2의 "명령 블록과 출력 인용 분리" 원칙이 자동화 게이트로 강제됨.

#### 1.2.2 의미상 어색한 치환

v4 sed가 자동으로 잡지 못하는 의미 손상 케이스가 있었다.

- `testerSelf` (v3 사용자 매핑)가 노드 호스트네임 자리에 박힘 → 후처리 sed로 `pve-nodeA`로 일괄 치환
- `kcy0122`가 노드명으로 사용된 사례(`02-vm-lifecycle/01-vm-create.md` 단일 노드 환경) → `pve-localhost`로 수동 보정 후 일관성 위해 `pve-nodeA`로 통일
- `pve-ksy` 노드명(v4 매핑 외 사용자 환경 식별자) → `pve-nodeB`로 후처리

이 패치들은 v4 정책의 sed 규칙으로는 잡히지 않는 **사용자 특정 환경 패턴**이다. 향후 v5 정책 갱신 시 환경별 식별자 등록 절차를 명시할 필요가 있다(§5.2 권고).

#### 1.2.3 한 줄로 식별 가능한 IP

v4 sed는 `10.10.[1-4]0.X`·`10.99.X.X`·`10.10.250.X`만 처리한다. 그 외 사설 대역(`192.168.X.X`·`172.16-31.X.X`)은 v4 매핑 외이며, 본 평가 시점에 Yellow·Red 자산에서 추가 사설 IP 잔재는 발견되지 않았다. 다만 향후 신규 자료에서 다른 사설 대역이 등장할 수 있어 v5 검증 패턴 확장이 필요하다.

#### 1.2.4 자격증명 패턴 사전 차단

`mask-v4.sh` [0] 단계의 5종 패턴(`Dpfdlxpzm` 같은 알려진 사례 + `password=...{6,}`·`token=...{20,}`·`secret=...{16,}`·`BEGIN PRIVATE KEY`)이 정상 작동했다. `06-references/05-rest-api.md`의 `password=YOUR_PASSWORD` 1건이 차단되어 `<YOUR_PASSWORD>` 형태로 수동 보정 후 통과. 이 사전 차단이 **v4의 가장 큰 가치**다.

### 3.2 v1 §3.5 페르소나 정합성 결론의 갱신

v1 결론은 **"현재 페르소나·현재 깊이로는 그대로 공개 비권고"**였다. v2에서 두 가지 갱신.

1. **Red 메타 시리즈가 단독으로 강력한 자산이 됨** — 환경 종속 자산이 제거되어 추상 거버넌스 자료가 되었다. 이는 시니어 인프라 엔지니어·SRE·테크니컬 라이터를 대상으로 한 자료로 분류 가능.
2. **AI 협업 disclosure가 frontmatter 수준에서 도입됨** — Red 시리즈 5개 모두 `ai_assistance` 명시. 사이트 단위 footer disclosure가 추가되면 v1 §6.4의 권고 대부분이 충족됨.

### 3.3 페르소나 추천 — 두 가지 선택지

#### 옵션 A: "운영 노트 정리하는 백엔드/SRE"

- 8개월 차 신입 페르소나 포기, 시니어급 콘텐츠 그대로 게시
- 자기소개·프로필을 "Proxmox·인프라 운영 노트를 정리하는 개발자"로 구성
- 채용 시장에서 시니어 포지션 어필 가능
- **현 자산과 가장 잘 맞는 페르소나**

#### 옵션 B: "신입의 시니어 멘토 협업 노트"

- 8개월 차 신입 페르소나 유지, AI·시니어 멘토 협업 사실을 명시
- 각 챕터에 "이 노트는 ___와의 협업으로 작성되었으며 본인이 사실 검증·재구성을 수행했다" 도입부
- 채용 시장에서 학습 능력·메타 인지·정직성 어필
- 한국 시장에서 다소 신선한 페르소나

권고는 **옵션 A**다. 자산의 깊이가 옵션 B의 학습 페르소나로는 설득력이 떨어지며, 외부에서 깊이만 보고 페르소나에 의문을 가질 가능성이 더 높다.

| 페르소나 옵션 | 잠재 채용 담당자 반응 | 동급 신입 비교 위축 | 시니어 신뢰성 |
| --- | --- | --- | --- |
| 현 8개월 차 신입 그대로 | "표절 의심" 가능성 (-) | 강함 (-) | 약함 (-) |
| 옵션 A (백엔드/SRE) | 시니어 포지션 가산점 (+) | 약함 (해당 없음) | 강함 (+) |
| 옵션 B (협업 노트) | 메타 인지 평가 (+) | 약함 (협업 명시) | 중간 |

옵션 A로 페르소나를 재정의하면 **본 자산이 채용 시장 음수 효과 → 양수 효과로 전환**된다. v1 §3.3의 양면성 우려가 옵션 A 채택으로 해소된다.

### 4.2 Red 메타 시리즈의 IP 가치

본 시리즈는 본 보고서가 평가하는 자산 중 **가장 큰 IP 가치**를 가진다. 근거 4가지.

1. **재사용성**: 격자·4분류·6 layer는 PVE 외 다른 인프라 SaaS·관리 도구·Kubernetes 콘솔에 그대로 이식 가능. 자산이 환경에 종속되지 않음.
2. **차별화**: 한국어 IT 블로그 시장에 동급 거버넌스 자료가 부재. 영문 시장에서도 단편적 블로그는 있으나 매뉴얼화된 형태는 드묾.
3. **실측 기반**: 메타 자산이지만 5노드 60시간 실측에서 도출되었다는 점이 추상 모범 사례 대비 신뢰성을 준다.
4. **확장 가능**: 본 4 자산 외 추가 자산(예: 사고 보고서 양식, 격자·분류 결합 결정 트리)을 후속 시리즈로 확장 가능. 5번째·6번째 챕터 추가 시 IP 두께가 누적됨.

### 4.3 학습 노트(Yellow)의 IP 가치

Yellow 14개 파일은 Proxmox VE 9.x 학습 노트로서 다음 가치를 가진다.

- **버전 특정 가치**: PVE 9.1 기준 작성. 9.x 라이프사이클 동안(2026~2028 추정) 유효.
- **트러블슈팅 가치**: `06-references/07-troubleshooting.md`는 NIC 아키텍처 포스트모템·KNET 토큰 타임아웃 같은 실측 사례 카탈로그. 영문권에도 단편적이라 한국어권에서 가장 강력한 지점.
- **REST API 가치**: `05-rest-api.md`·`06-rest-api-nodes-qemu.md`는 인증·UPID·Task 추적 같은 깊이 있는 항목 포함. CMP 같은 PVE 래퍼를 만들거나 검증하는 모든 사람에게 직접 가치.

## 5. 한국 시장 어필 포인트

### 5.1 한국어 Proxmox 콘텐츠 생태계 분석

| 영역 | 한국어 자료 수준 | 본 시리즈 위치 | 격차 |
| --- | --- | --- | --- |
| Proxmox 설치 (블로그·유튜브) | 다수 | 동등 또는 약간 우위 | 미미 |
| 스토리지·백업 (벤더 한국어 매뉴얼) | 중간 | 우위 (실측 포함) | +20~30% |
| HA·자동화 | 부족 | 압도적 우위 | +40~50% |
| 트러블슈팅 카탈로그 | **거의 없음** | 압도적 우위 | +70~80% |
| **인프라 거버넌스 메타 자료** | **사실상 부재** | **유일** | **+95%** |

### 5.2 차별화 어필 포인트 4가지

#### 5.2.1 메타 거버넌스 (Red 시리즈)

한국어로 "L×R 격자"·"4 테스트 분류"·"6 Layer 검증 사슬"·"챕터 표준 구조"를 통합 다루는 자료가 없다. 본 시리즈가 한국 시니어 인프라 엔지니어·QA 리드·테크니컬 라이터의 검색 유입을 독점할 가능성.

검색 유입 시나리오 (롱테일):
- "Blast Radius Reversibility 격자"
- "인프라 SaaS 테스트 분류"
- "PVE 검증 사슬"
- "운영 매뉴얼 표준 구조"

#### 5.2.2 트러블슈팅 카탈로그 (Yellow 06)

NIC 아키텍처 포스트모템·KNET 토큰 타임아웃 같은 매우 구체적 사례가 한국어로 검색 가능한 것이 거의 없다. **"Proxmox NFS alias 권한 비대칭"**·**"corosync ring1 storage 충돌"** 같은 매우 구체적 검색어에서 본 시리즈가 한국어 단일 결과가 될 가능성.

#### 5.2.3 REST API 깊이 (Yellow 06.05·06)

PVE REST API의 Ticket 인증·CSRF·UPID 추적·Task 라이프사이클을 깊이 다룬 한국어 자료는 거의 없다. CMP·자동화 도구 개발자에게 직접 가치.

#### 5.2.4 한국어 IT 블로그의 양식적 차별화

본 시리즈는:
- frontmatter contract (v4 marker, ai_assistance, masking_policy 등)
- 챕터 표준 구조
- 격자·분류·검증 사슬 표

같은 양식 자체가 한국어 블로그에서는 드물다. **"운영 매뉴얼처럼 작성된 블로그"**라는 양식적 포지션 자체가 차별화.

### 5.3 한국 채용 시장 효과

§3.4에서 옵션 A 페르소나 채택 시:
- 시니어 백엔드·DevOps·SRE 채용 시 **본 시리즈 URL 1개로 입증할 수 있는 역량 범위가 매우 넓다**
- 한국 IT 회사 시니어 면접에서 사전 자료로 사용 가능 ("이 글을 보고 면접 준비했다")
- 본인 회사가 Proxmox·CMP·인프라 SaaS·DevOps 도구 회사라면 직접 매칭 가능

### 5.4 한국 시장 한계

다음은 한국 시장 어필 한계로 인지해야 한다.

- **시니어 시장 협소**: 한국 IT 채용 시장에서 시니어 SRE·인프라 엔지니어 절대 수가 적다. 본 시리즈의 타겟층 자체가 작음.
- **블로그 검색 유입 < SNS·커뮤니티**: 한국에서는 블로그 직접 검색보다 인포컴(Inflearn·F-lab)·커뮤니티(GeekNews·okky) 경유 유입이 큼. SEO 최적화만으로는 부족할 수 있음.
- **콘텐츠 양식의 진입 장벽**: 본 시리즈의 깊이·양식이 입문자에게는 진입 장벽이 됨. 신입 개발자 입장에서 "어렵다"라는 인상으로 이탈 가능.

#### 6.2.1 한국어 그대로의 글로벌 도달

한국어 콘텐츠는 글로벌 도달이 본질적으로 제약된다. 다만:

#### 6.2.2 영문 번역 시리즈

본 시리즈를 영문으로 번역하면 글로벌 어필 매우 강력. 특히 Red 메타 시리즈는:

- 환경 종속 0% (번역 후 적용 마찰 없음)
- 도메인 일반론 (Proxmox 외 적용 가능)

번역 우선순위 권고:
1. Red 메타 시리즈 5개 챕터 (가장 높은 글로벌 가치)
2. Yellow 06 (트러블슈팅·REST API) — 영문권 운영자 블로그 시장에 직접 진입
3. Yellow 04~05 (스토리지·HA) — 표준 운영 자료 시장
4. Yellow 01~03 — 우선순위 낮음 (영문권에 동급 자료 다수)

#### 6.2.3 글로벌 채용 시장

영문 번역 시리즈가 있으면:
- LinkedIn 프로필에 영문 URL로 연결 가능
- 글로벌 원격 시니어 SRE·DevOps 포지션 지원 시 자료
- 콘퍼런스·미트업 발표 자료로 활용 가능 (KubeCon Korea·DevOpsDays Asia 등)

### 6.3 글로벌 한계

- **번역 비용**: 영문 번역은 자동 번역 + 인간 검수 조합으로 적게 잡아도 챕터당 수 시간. 5개 챕터 + Yellow 14개 파일 = 약 50~80시간.
- **영문권 시니어 SRE 콘텐츠 시장 포화**: KubeCon·DevOps 콘퍼런스에서 시니어 콘텐츠가 풍부. 본 시리즈가 자리 잡으려면 양식적 차별화(메타 자산 추출이라는 접근)를 강조 필요.
- **레딧·해커뉴스 진입 장벽**: 영문권 IT 커뮤니티에서 한국발 콘텐츠가 자체 동력으로 도달하기 어려움. 글로벌 동료 네트워크 + 의도적 공유가 필수.

본 자산은 **회색 영역**이다. Red 메타 시리즈는 사내 핸드북에서 메타를 추출했다고 본 보고서 §1에서 명시했고, 이것이 회사 업무 산출물의 추상화로 해석되면 회사 동의 영역에 들어간다.

### 7.4 정보통신보안법 직접 평가

질문: "v4 적용 후 본 자산이 정보통신망법(특히 정보통신망 이용촉진 및 정보보호 등에 관한 법률)에 직접 저촉되는가?"

| 조항 | 위반 여부 | 근거 |
| --- | --- | --- |
| §22 (개인정보 수집·이용) | 위반 없음 | 본 사이트는 개인정보를 수집·이용하지 않음. |
| §28 (안전조치 의무) | 위반 없음 | 비밀번호 평문 노출 해소. v4 [0] 차단 정착. |
| §49 (비밀침해) | 위반 없음 | 본 자산이 타인의 비밀을 침해할 직접 근거 없음. |

**결론**: v4 적용 후 본 사이트가 직접 정보통신망법에 저촉되는 직접 근거는 발견되지 않는다. 다만 §7.1 영업비밀·저작권 영역이 별개로 잔여 위험이며, 이는 회사 동의로만 해소 가능.

# 옵션 B: frontmatter 일괄 갱신
for f in docs/notes/linux/proxmox/07-cmp-test/*.md docs/notes/blog-ops/*.md; do

### 10.3 가장 큰 가치의 단일 자산
